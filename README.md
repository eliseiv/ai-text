# docs-rag — бэкенд iOS-приложения «AI-конспекты и ответы по материалам»

Пользователь собирает в **тему** PDF (с текстовым слоем), вставленный текст и публичную веб-статью.
Сервер извлекает текст, готовит его к вопросам, строит **AI-конспект** и отвечает на **вопросы**
строго по выбранным материалам. Каждый тезис подкреплён **проверенной сервером цитатой**: точный
фрагмент версии источника, смещения в тексте и для PDF — физическая и печатная страница.
Интерфейс и ответы на русском, цитаты на языке оригинала.

Сервис собран из `service-template`. Ядро (auth по deviceId и Sign in with Apple, кошелёк с
идемпотентным ledger, policy, биллинг StoreKit/Adapty/CloudPayments, observability) изменено
только в биллинге (см. «Оплата»). Весь домен лежит в `src/app/domain/` и подключён через
`DomainRegistry`.

## Архитектура

```
iOS ──HTTPS──► api (FastAPI)  ──┐   одна транзакция: строка + задача в очереди
                                ├──► PostgreSQL: темы, источники, версии, фрагменты (FTS),
worker (python -m               │                 чат, конспекты, domain_jobs, ядро (ledger…)
  app.domain.worker) ◄──────────┘
   ├─ импорт: PDF (pypdf) / текст / веб (SSRF-safe fetch + trafilatura) → версия → фрагменты
   ├─ ответы и конспекты: GenerationService ядра → SourcesProvider → OpenAI (Responses API)
   └─ очистка удалённого (файлы, версии, индексы, история)
файлы оригиналов: том /data/files (общий для api и worker), временные подписанные ссылки
```

| Модуль (`src/app/domain/`) | Что делает |
|---|---|
| `routers/*` | HTTP API (см. ниже) |
| `topics.py`, `sources.py`, `chat.py`, `summaries.py` | сервисы; проверки до постановки в очередь |
| `ingest*.py` | извлечение текста: PDF (страницы, печатные номера, скан-детектор), веб (SSRF-защита) |
| `text.py` | нарезка на фрагменты, нормализация и поиск цитат с точными смещениями |
| `context.py` | что видит модель: только выбранные, готовые, живые версии своей темы |
| `provider.py`, `prompts.py`, `llm.py` | провайдер генерации: ответ / конспект (map-reduce), structured outputs |
| `citations.py` | серверная сверка цитат, нумерация сносок |
| `runs.py`, `worker.py`, `jobs.py` | фоновые задачи, повтор, восстановление после падения |
| `access.py`, `pricing.py` | доступ (та же policy ядра), цена операций в кредитах |
| `demo.py` | демо-тема с готовым конспектом (цитаты проходят ту же сверку) |
| `purge.py` | физическое удаление после согласованного срока |

## API (кратко; полная схема — `/docs`)

| | |
|---|---|
| `POST/GET /v1/topics`, `GET/PATCH/DELETE /v1/topics/{id}` | темы: создать, найти (`query` ищет по темам и материалам), переименовать, удалить |
| `POST /v1/topics/{id}/sources/pdf \| text \| web` | импорт (multipart PDF / JSON) |
| `GET /v1/topics/{id}/sources` | материалы и статусы: `uploading → extracting → indexing → ready / failed` |
| `PATCH /v1/sources/{id}` (`selected`), `DELETE`, `POST …/retry` | выбор для ответов, удаление, повтор |
| `GET /v1/sources/{id}/content?versionId=` | текст версии и страницы — для экрана «Цитата / оригинал» |
| `GET /v1/sources/{id}/original` → `GET /v1/files/{token}` | временная ссылка на оригинал |
| `POST/GET /v1/topics/{id}/messages`, `…/{mid}`, `…/cancel`, `…/retry` | чат: вопрос, история (курсор), отмена, повтор |
| `POST /v1/topics/{id}/summaries`, `GET …/summaries/latest`, `/v1/summaries/{id}[/cancel\|/retry]` | конспект |
| `GET /v1/limits`, `GET /v1/plan`, `DELETE /v1/account/data` | лимиты, тариф и остаток, удаление данных |
| ядро: `/v1/auth/*`, `/v1/subscription*`, `/v1/products`, `/v1/billing/*`, `/v1/wallet` | вход и восстановление, оплата |

Ответ (`MessageView.answer`) соответствует согласуемым полям ТЗ: `id` (answer_id), `text` со сносками
`[n]`, `sourceVersionIds`, `citations[{sourceId, versionId, quote, page{physical,label}?, offsets}]`,
`status`, `usage`. Клиент цитаты не достраивает.

## Гарантии (и где они проверяются тестами)

- **Цитаты реальны.** Модель возвращает `{chunk, quote}`. Сервер ищет цитату в тексте фрагментов из
  контекста, прощая только типографику (регистр, ё/е, кавычки, тире, переносы PDF), и хранит
  оригинальный срез с точными смещениями. Выдуманная цитата отбрасывается, тезис без цитат тоже.
  Отдельный проход модели проверяет, *подтверждает* ли цитата вывод (`CITATION_SUPPORT_CHECK`).
  Если ничего не осталось, ответ: «В выбранных материалах нет ответа на этот вопрос». При
  противоречиях показываются обе позиции с источниками. — `test_units.py`, `test_provider.py`
- **Изоляция и prompt injection.** Контекст собирается SQL-запросами с фильтром по пользователю и
  теме. У модели нет инструментов, ссылка на фрагмент вне контекста отбрасывается. Текст
  документа — данные: теги-разделители нейтрализуются. — `test_users_are_isolated_…`
- **Удалённое не используется.** Удалённые и исключённые материалы не попадают в новые ответы, в том
  числе при повторе старого сообщения. Прошлые ответы с такими источниками не подаются в историю.
  Старые цитаты помечаются `sourceDeleted`, текст — `410 source_deleted`. Удалённая тема сразу
  отдаёт `404` по всем ссылкам и затем физически очищается. — `test_deleted_…`
- **Деньги.** Списание происходит только за готовый результат, внутри `GenerationService` ядра.
  Ошибка, отмена и блокировка стоят 0. Ключ идемпотентности `answer:{id}:{attempt}`: повтор
  задачи и повтор запроса (`Idempotency-Key`) не дублируют ни обработку, ни списание. Упавший
  воркер восстанавливается без двойного списания. Блокировка (`blocked`) сохраняет вопрос; после
  покупки клиент явно вызывает `retry` — автоматического расхода нет. — `test_failures_…`,
  `test_orphaned_run_…`, `test_blocked_…`
- **Частичная готовность.** Ошибка одного файла не блокирует готовые (`skippedSources`). Страницы
  PDF без текстового слоя перечислены (`pagesWithoutText`). Конспект сообщает покрытие
  (`coverage.partial`), ответ — `partialContext`, если материалы не поместились целиком.
- **Статус переживает сворачивание приложения:** вся обработка идёт на сервере, клиент опрашивает объект.
- **Технические логи** не содержат текстов документов и ответов: только идентификаторы и счётчики.

## Запуск

```bash
cp .env.example .env            # LLM_PROVIDER=fake — работает без ключа модели
docker compose up --build -d    # postgres + redis + migrate + api + worker
curl -fsS http://127.0.0.1:8000/ready
```

Для настоящей модели: `LLM_PROVIDER=openai`, `OPENAI_API_KEY=…` (+ `OPENAI_API_KEY_BACKUP`).
Модели: `OPENAI_MODEL=gpt-5.1` (ответы и конспекты), `OPENAI_CHECK_MODEL=gpt-5-mini` (проверка
цитат). Сервис размещается на зарубежном сервере, прокси не нужен (`OPENAI_PROXY_URLS`
пустой). Запросы идут с `store=false`: OpenAI не хранит ответы в своём хранилище.

```bash
make install && make ci          # ruff + mypy + pytest (testcontainers: нужен Docker) + coverage
uv run python -m app.domain.worker   # воркер без docker
```

Прод: `docker-compose.prod.yml` (сервис `worker` и том `filedata`) — см. `infra/deploy/README.md`.
Маршрут `POST /v1/generate` из шаблона монтируется только при `ENVIRONMENT=dev`: на нём тесты ядра
проверяют инварианты биллинга. В prod его нет.

## Оплата

Подписка с кредитами за период плюс пакеты кредитов. Каналы: App Store, Adapty,
CloudPayments/broadapps. Цены и лимиты — конфигурация. Предложение с расчётом себестоимости,
правила возвратов и одного начисления на покупку описаны в [`docs/pricing.md`](docs/pricing.md).

Доработки ядра в этом сервисе:
- **Срок доступа по оплате CloudPayments** — ровно один период продукта (`period`: `P1W`, `P1M`,
  `P1Y`), а не фиксированные 30 дней.
- **Возвраты** по вебхукам Adapty и CloudPayments и по отозванным транзакциям App Store: кредиты
  покупки отзываются (не ниже нуля), подписка закрывается, повтор ничего не списывает дважды.
- **Одна покупка Apple — одно начисление.** Покупка, пришедшая и через StoreKit, и через Adapty,
  начисляется один раз. Пакеты, купленные через Adapty SDK (`non_subscription_purchase`),
  начисляются вебхуком.

## Что нужно согласовать (ТЗ оставляет открытым)

1. **Хранение данных у OpenAI** (запросы идут с `store=false`).
2. **Срок физического удаления** — `PURGE_DELAY_SECONDS` (в prod-примере 24 ч). Платёжные записи не
   удаляются.
3. **Вход и восстановление библиотеки.** В ядре: вход по deviceId и привязка Sign in with Apple, после
   переустановки вход через Apple возвращает те же темы.
4. **Отдельная оценка до включения:** OCR, DOCX, аудио, YouTube, аудиообзоры, карточки.
